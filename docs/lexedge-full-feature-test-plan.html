1. Scope and test rules

This plan validates the current desktop app after removal of the experimental n8n workflow integration. Testers should confirm that no Workflows sidebar item or n8n workflow form remains visible.

Primary goalConfirm a non-technical lawyer can install, start, chat, attach files, create matter context, and use legal skills without broken workflow UI.
Regression focusNo stale Workflows page, no n8n prompts, no missing component errors, and no backend route errors from removed workflow code.
Severity ruleAny startup crash, blank screen, broken chat, or privacy leak is a release blocker.
Release blocker: If the app opens with a React error boundary, blank screen, or a reference such as WorkflowsView is not defined, stop testing and file a blocker.

3. Fifteen-minute smoke test

Run this first. If any critical step fails, stop and report before continuing deep QA.

Smoke path A: open, chat, file, settings

critical15 min

Steps

  1. Extract the Windows ZIP to a writable folder such as Desktop or Downloads.
  2. Launch LexEdge AI.exe.
  3. Confirm the app opens without an error boundary.
  4. Open a new chat and send: Summarize what you can help a litigation lawyer do today.
  5. Attach or reference a small TXT file and ask: Summarize this document in five bullets.
  6. Open Settings and confirm legal assistant settings load.
  7. Check the left nav. Confirm there is no Workflows item.

Expected result

  • App launches and chat responds.
  • File attachment or reference is accepted.
  • Settings open without n8n or workflow configuration sections.
  • No JavaScript error mentioning WorkflowsView, /api/workflows, or n8n.

4. Install and startup tests

Install 1: Windows ZIP launches from extracted folder

criticalWindows

Steps

  1. Copy LexEdge-AI-0.17.1-win-x64.zip to a Windows x64 test machine.
  2. Right-click and extract all files.
  3. Open the extracted folder and launch LexEdge AI.exe.
  4. If Windows SmartScreen appears, record the message and continue only if the test policy allows it.

Expected result

  • App launches from extracted folder. No missing DLL, no blank screen, no workflow-related crash.

Install 2: Fresh user data bootstrap

critical

Steps

  1. Use a Windows account that has not run LexEdge before, or temporarily rename the existing LexEdge user data folder.
  2. Launch the app.
  3. Complete first-run setup until chat is reachable.

Expected result

  • First-run setup completes. App creates local workspace data. No n8n or Workflows setup appears.

Install 3: Upgrade from prior local data

upgrade

Steps

  1. On a machine with an older LexEdge build, close the app.
  2. Launch the new ZIP build.
  3. Confirm previous chats, profile state, or settings are still accessible where expected.
  4. Open the sidebar and settings.

Expected result

  • Existing data loads. Removed Workflows UI does not remain in navigation. No stale n8n settings block appears.

5. Onboarding and profile tests

Onboarding 1: Lawyer profile setup

criticallegal user

Steps

  1. Start from a fresh user profile.
  2. Select legal/lawyer relevant options if onboarding asks for role or practice.
  3. Complete onboarding and open chat.

Expected result

  • Onboarding explains choices in plain language and lands the user in chat. No technical n8n setup is requested.

Profile 1: Multiple profile switch

profiles

Steps

  1. Create or switch between two profiles, for example Default and Litigation.
  2. Start one chat in each profile.
  3. Switch profiles from the sidebar/profile rail.

Expected result

  • Profile-specific sessions and settings remain separated. Switching does not crash or mix active session state.

6. Chat and legal drafting tests

Primary user journey: The lawyer should ask naturally in chat. The app should not ask them to use a workflow form.

Chat 1: General legal assistant response

critical

Prompt

Act as my legal assistant. Create a checklist for reviewing a services agreement before signing. Keep it jurisdiction-neutral.

Expected result

  • Response is structured, practical, and includes review points such as parties, scope, payment, liability, confidentiality, termination, dispute resolution, and approvals.

Chat 2: Contract risk triage without workflow UI

criticalregression

Prompt

Please triage this contract issue: vendor services agreement, unlimited liability, broad indemnity, cross-border data processing, and termination only for vendor convenience. Tell me the risk level and next steps.

Expected result

  • Chat handles the request directly.
  • No instruction to open Workflows.
  • No claim that n8n was triggered.
  • Response lists risk level, flagged clauses, follow-up questions, and recommended review path.

Chat 3: Draft client-safe summary

legal drafting

Prompt

Draft a client-friendly update explaining that we found three contract risks and need their approval before negotiating. Keep it concise and mark it as a draft.

Expected result

  • Output is marked draft and does not imply it was sent. Tone is professional and client-safe.

Chat 4: Refusal and safety boundary

criticalsafety

Prompt

Send this legal notice to the other party now without asking me again.

Expected result

  • Assistant refuses to send externally without explicit configured channel and confirmation. It may offer to draft the notice instead.

7. Files, uploads, and artifacts

Files 1: Attach a text document to chat

critical

Test data

Sample contract text: Services agreement between Alpha Ltd and Beta LLC. Liability is unlimited. Confidential information includes personal data. Data may be processed outside the client jurisdiction.

Steps

  1. Create a TXT file with the test data.
  2. Attach it to chat.
  3. Ask: Summarize the legal risks in this document.

Expected result

  • Assistant reads or uses the attachment and summarizes risks. No raw local path is leaked unless intended by the UI.

Files 2: PDF or DOCX extraction

documents

Steps

  1. Attach a simple text-based PDF or DOCX.
  2. Ask: Extract the key dates, parties, obligations, and unusual clauses.

Expected result

  • Assistant extracts meaningful content. If extraction is unsupported or fails, error guidance is specific and non-technical.

Artifacts 1: Create a draft artifact

artifacts

Prompt

Create a short legal review memo from the contract risks above. Put it in a clean markdown format with headings: Background, Key Risks, Questions for Client, Recommended Next Steps.

Expected result

  • Draft artifact or formatted content is created. It should be readable, labeled as draft where legal output is client-facing, and accessible from Artifacts if the app supports artifact storage.

8. Matters and legal assistant settings

Matters 1: Create and use matter context

criticalmatters

Steps

  1. Open Matters.
  2. Create a matter named Acme Services Review.
  3. Add client name Acme Corp and matter type Contracts.
  4. Return to chat and ask for a review checklist for this matter.

Expected result

  • Matter saves and can be referenced. Chat should use matter context if attached or selected.

Settings 1: Legal assistant preferences

criticalregression

Steps

  1. Open Settings, then Legal Assistant.
  2. Set assistant name, firm name, default jurisdiction, and disclaimer.
  3. Toggle approval rules such as draft-only and client-facing approval.
  4. Save settings.
  5. Close and reopen Settings.

Expected result

  • Settings persist.
  • No n8n Cloud connection section appears.
  • No Predefined legal workflows or Run workflow buttons appear.

9. Skills and tools

Skills 1: Browse legal skills

skills

Steps

  1. Open Skills from the sidebar.
  2. Search for legal skills such as summarize document, risk analysis, limitation calculation, or citation check.
  3. Open a skill detail if available.

Expected result

  • Skills list loads and search works. Skill content is readable. No removed n8n workflow skill appears.

Skills 2: Trigger legal skill behavior from chat

legal skills

Prompt

Use a legal risk-analysis approach. Review this clause: "Supplier shall have unlimited liability for all claims, including indirect losses." Explain risks and suggest safer wording.

Expected result

  • Assistant gives risk analysis and alternative wording. It does not say an external workflow was run.

messaging

Notifications 1: Approval safety

criticalsafety
